02 / Слои проверки

Каждый слой отвечает на свой вопрос

Ни один документ не доказывает всю цепочку. Нажмите на слой, чтобы увидеть его границу.

Что доказывает

Runtime SBOM описывает опубликованные файлы, а отдельно помеченный build SBOM — инструменты и зависимости сборки. Форматы: SPDX и CycloneDX.

Граница проверки

SBOM не доказывает, что production собран из указанного репозитория или вообще содержит этот артефакт.

Что доказывает

Какие известные уязвимости Grype нашёл в runtime и build SBOM на момент сканирования (с фиксацией версии базы).

Граница проверки

Ноль совпадений не означает отсутствие уязвимостей. Ошибка или недоступная база никогда не отображаются как чистый результат.

Что доказывает

Какой workflow собрал артефакт с этим дайджестом, из какого коммита и с какими входными материалами.

Граница проверки

Provenance требует проверки подписи и доверия к указанной CI-идентичности; сам по себе JSON не аутентичен.

Что доказывает

Независимая сборка из тех же объявленных входных данных создаёт байт в байт тот же артефакт.

Граница проверки

Совпадение подтверждает процедуру сборки, но ещё не сообщает, какой именно артефакт развёрнут.

Что доказывает

Данные подписаны ожидаемым GitHub workflow через короткоживущую OIDC-идентичность и не были изменены.

Граница проверки

Подпись аутентифицирует дайджест и утверждение (statement), а не истинность всех сведений внутри них.

Что доказывает

Какие именно файлы HTML, JavaScript, CSS и исходники Worker относятся к одному подписанному релизу.

Граница проверки

Манифест задаёт ожидаемые байты. Реальные ответы production нужно скачать и сравнить отдельно.

Что доказывает

Независимый процесс проверил идентичность, все связанные дайджесты и фактические ответы production; полный JSON и читаемый отчёт сохраняются в подписанном неизменяемом verification-релизе.

Граница проверки

Результат относится к указанному релизу и моменту проверки; компрометация после неё требует нового запуска.

Что доказывает

Обычный Subresource Integrity проверяет входной скрипт и таблицу стилей. importmap.integrity задаёт SHA-384 для каждого JS-модуля, включая транзитивные импорты, а CSP фиксирует хеш самой import map.

Граница проверки

SRI не защищает HTML-документ, который содержит ожидаемый хеш — его проверяет внешний верификатор. CSS, загруженный через @import или url(), требует отдельного контроля.

03 / Независимая проверка

Не верьте этому сайту.
Проверьте его.

Проверено CI: подписи Cosign, provenance, SBOM, сканирование CVE и воспроизводимая сборка. Проверено сейчас в браузере: идентичность текущего deployment, SHA-256 всех production-файлов, SHA-384 Subresource Integrity и полный importmap.integrity для JavaScript-модулей.

Онлайн-верификатор скачивает production-файлы напрямую и не исполняет код с проверяемого сайта. Для независимой локальной проверки подписей и сборки используйте команду справа.

Проверить текущий deployment онлайн
shell
$ git clone https://github.com/metalagman/webappsec
$ cd webappsec
$ git checkout <tag> && npm ci && npm run tools:signing
$ npm run verify:release -- --release <tag> --rebuild
!
