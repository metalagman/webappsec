01 / Маршрут доказательства

Одна идентичность релиза на каждом шаге

  1. 01Исходный кодcommit SHA
  2. 02CI-сборкаSLSA provenance
  3. 03Артефактdigest + signature
  4. 04DeploymentWorker version
  5. 05Браузерbytes + SRI

Ключ цепочки — digest канонического manifest. Если commit, artifact, provenance или production указывают на разные digest, verifier завершится с ошибкой.

02 / Слои проверки

Каждый слой отвечает на свой вопрос

Ни один документ не доказывает всю цепочку. Нажмите на слой, чтобы увидеть его границу.

Что доказывает

Runtime SBOM описывает опубликованные файлы, а отдельно помеченный build SBOM — инструменты и зависимости сборки. Форматы: SPDX и CycloneDX.

Граница проверки

SBOM не доказывает, что production собран из указанного репозитория или вообще содержит этот артефакт.

Что доказывает

Какие известные уязвимости Grype и его версия базы сопоставили runtime и build SBOM в момент сканирования.

Граница проверки

Ноль совпадений не означает отсутствие уязвимостей. Ошибка или недоступная база никогда не отображаются как чистый результат.

Что доказывает

Какой workflow собрал digest артефакта, из какого commit и с какими входными материалами.

Граница проверки

Provenance требует проверки подписи и доверия к указанной CI identity; сам по себе JSON не аутентичен.

Что доказывает

Независимая сборка тех же объявленных входов создаёт байт-в-байт тот же артефакт.

Граница проверки

Совпадение подтверждает процедуру сборки, но ещё не сообщает, какой артефакт был развёрнут.

Что доказывает

Payload подписан ожидаемым GitHub workflow через короткоживущую OIDC identity и не был изменён.

Граница проверки

Подпись аутентифицирует digest и statement, а не истинность всех утверждений внутри них.

Что доказывает

Какие точные HTML, JavaScript, CSS и Worker inputs относятся к одному подписанному релизу.

Граница проверки

Manifest задаёт ожидаемые байты. Реальные ответы production нужно скачать и сравнить отдельно.

Что доказывает

Независимый процесс проверил identity, все связанные digest и фактические ответы production.

Граница проверки

Результат относится к указанному релизу и моменту проверки; runtime-компрометация после неё требует нового запуска.

Что доказывает

Браузер исполнил подключённый script или stylesheet только при совпадении его SHA-384.

Граница проверки

SRI не защищает HTML-документ, который содержит ожидаемый hash. Его проверяет внешний verifier.

03 / Независимая проверка

Не верьте этому сайту.
Проверьте его.

Команда получает evidence из GitHub Release, проверяет Cosign policy и provenance, затем скачивает production-файлы напрямую. Код с проверяемого сайта не исполняется.

shell
$ git clone https://github.com/metalagman/webappsec
$ cd webappsec
$ git checkout <tag> && npm ci && npm run tools:signing
$ npm run verify:release -- --release <tag> --rebuild
!
